# Personal Site — Technical Remediation Plan

This document is the working execution plan for the site-wide technical audit. It is intentionally implementation-oriented: every item should end in code, tests, CI checks, or an explicit decision that the responsibility belongs to another repository/package.

## Ground rules

1. Preserve behavior unless a task explicitly fixes a bug or security issue.
2. Do not move reusable parsing/geographic knowledge into local `shared/` code just to make it reusable inside this repository.
3. Reusable free-text semantics belong to `@whiteslove/parsing-lexicon`.
4. Canonical geography, hierarchy, coordinates, boundaries, spatial relations and reusable geo algorithms belong to `@whiteslove/geo-catalog`.
5. Apartment ingestion/normalization/search remains owned by Flat Finder; Personal Site should stay a consumer/adapter.
6. Prefer small behavior-preserving refactors with tests over large rewrites.
7. Every cleanup batch must pass lint, tests and build before merge.

## Priority model

- **P0** — security/data-loss/runtime correctness risk.
- **P1** — production reliability, performance, unbounded resource use, architecture violations.
- **P2** — maintainability debt: god files, duplication, decomposition, misplaced domain logic.
- **P3** — tails, naming, consistency, dead code and cosmetic cleanup.

## Phase 1 — P0 security and destructive-operation boundaries

### PDF document IDs / filesystem boundary

- [ ] Validate every PDF `doc_id` as a UUID before it reaches filesystem helpers.
- [ ] Make filesystem helpers accept only validated IDs.
- [ ] Require document existence before destructive delete.
- [ ] Add traversal/invalid-ID regression tests.

### SVG editor XSS boundary

- [ ] Introduce one centralized SVG sanitization boundary.
- [ ] Sanitize before every `v-html`/`innerHTML` insertion.
- [ ] Reject `<script>`, `<foreignObject>`, event-handler attributes, unsafe external hrefs and unsafe URL-bearing CSS.
- [ ] Add malicious SVG regression fixtures.

---

## Phase 2 — P1 runtime resource budgets

### Converter/FastAPI backend

- [ ] Add hard per-file and per-request byte limits to media/data/document conversion.
- [ ] Stream uploads to temporary files instead of reading arbitrary files fully into RAM.
- [ ] Avoid accumulating all converted outputs in memory when a streaming/temp-file path is available.
- [ ] Bound concurrent CPU/process-heavy conversions with a semaphore/worker boundary.
- [ ] Add subprocess timeouts.
- [ ] Make DOCX→PDF runtime capability match the Docker image (install supported runtime dependency or disable the feature explicitly).
- [ ] Add container resource limits where practical.

### Public fan-out/cache endpoints

- [ ] Cap country-index bundle key counts and validate keys before caching/fan-out.
- [ ] Bound request-level external concurrency.
- [ ] Prevent persistent lock/cache cardinality from growing without limit.
- [ ] Apply equivalent cardinality protections to DockerHub/cache-backed public endpoints.

---

## Phase 3 — P1 memory/cache correctness

- [ ] Replace unbounded `Map` caches in `flats-feed` with bounded TTL/LRU caches.
- [ ] Bound `publicIdCache` and normalize cache keys.
- [ ] Replace/clean up the process-local translation rate-limit map.
- [ ] Verify `X-Forwarded-For` trust assumptions at the reverse-proxy boundary.
- [ ] Decide whether multi-replica state belongs in Redis/Nitro storage rather than process memory.

---

## Phase 4 — P1 database/query performance

### Jobs

- [ ] Split page retrieval from expensive statistics/facets.
- [ ] Cache statistics by normalized filter key for a short TTL.
- [ ] Stop materializing `SELECT *` for statistics paths.
- [ ] Downsample salary trends by day/week rather than aggregating one JSON object per matching row.
- [ ] Replace deep OFFSET pagination with cursor/keyset pagination where applicable.
- [ ] Remove substring geography scans where canonical indexed fields can be used; otherwise add the appropriate trigram/index support.

### Hiring

- [ ] Stop deduplicating the entire active candidate table on each read.
- [ ] Move canonical/current-candidate dedupe to ingestion or a maintained read model.
- [ ] Split/cached facets and statistics as for Jobs.

### Schema lifecycle

- [ ] Remove DDL and backfills from request paths.
- [ ] Move schema changes/backfills into versioned migrations/deploy jobs.
- [ ] Reduce runtime DB privileges after migrations are externalized.

**Validation:** use `EXPLAIN (ANALYZE, BUFFERS)` against staging/production-like data before claiming query-latency improvements.

---

## Phase 5 — P1 deployment and operability

- [ ] Pin every deployed service to immutable SHA/digest instead of mutable `latest`.
- [ ] Maintain a deployment manifest mapping service → image revision.
- [ ] Make rollback use that immutable manifest.
- [ ] Split liveness from readiness.
- [ ] Readiness must verify critical dependencies, not just process existence/OpenAPI availability.
- [ ] Add queue-worker health signals such as last dispatch/completion and pending/dead counts.
- [ ] Add lease renewal/heartbeat before horizontally scaling long-running queue workers.

## Phase 6 — P2 package-boundary cleanup

Every candidate must be classified as one of: **keep local**, **local shared**, **→ parsing-lexicon**, **→ geo-catalog**, **→ Flat Finder**, **→ AI worker**.

### Move to `@whiteslove/parsing-lexicon`

Audit and remove reusable local logic for:

- [ ] profession canonicalization/family matching;
- [ ] seniority semantics and contradiction rules that are source-independent;
- [ ] skill canonicalization/extraction that is source-independent;
- [ ] candidate role/target-context semantics;
- [ ] multilingual aliases, script/language heuristics and transliteration helpers;
- [ ] generic geography display/alias choice rules;
- [ ] generic housing/job/hiring semantic regexes and keyword dictionaries.

Initial hotspot: `app/utils/locationLabels.ts` currently understands Cyrillic variants, Uzbek locality suffixes, alias affinity and probe forms. That domain knowledge should be exposed by the shared lexicon instead of reimplemented by the website.

### Move to `@whiteslove/geo-catalog`

Audit and remove reusable local logic for:

- [ ] geo hierarchy traversal (`children`/`descendants` APIs instead of consumer knowledge of ID prefixes);
- [ ] reusable distance/spatial utilities;
- [ ] canonical boundary/hierarchy operations;
- [ ] reusable city/zone spatial derivation if it is not presentation-specific.

Initial hotspot: `app/composables/flats/useDistrictZones.ts` should keep Vue state and visual layer construction, but should not need to infer catalog hierarchy from `parentId` plus `id.startsWith(...)`.

### Keep source-specific adapters local

- [ ] Keep scraping chrome cleanup and source payload quirks next to the relevant source adapter.
- [ ] Do not move source-specific selectors/HTML cleanup into the shared lexicon unless the behavior is genuinely reusable semantics.

## Phase 7 — P2 god files and decomposition

Audit by responsibility count, not line count alone.

Initial targets:

- [ ] `app/pages/flat-finder/index.vue` — reduce orchestration/UI coupling without rewriting the page.
- [ ] `server/routes/flats-feed.get.ts` — separate proxy contract, cache, compatibility shaping and request orchestration.
- [ ] `server/routes/hiring-feed.get.ts` — separate HTTP parsing, query construction, presentation and compatibility logic.
- [ ] `server/jobs/infrastructure/database.ts` — split schema/migrations, page queries, stats/facets and write concerns.
- [ ] `server/hiring/infrastructure/database.ts` — split read model/querying from schema/backfill/write concerns.
- [ ] `server/utils/hiringNormalize.ts` — keep application orchestration while moving shared semantics upstream and source cleanup toward adapters.

Rules for decomposition:

- one module should have one dominant reason to change;
- avoid boolean-mode functions that implement several workflows;
- prefer named state transitions/helpers to scattered reactive mutations;
- do not extract tiny wrappers that merely increase indirection.

## Phase 8 — P2 duplication

- [ ] Find literal and semantic duplicates in fetch/error/loading handling.
- [ ] Consolidate repeated feed pagination/request-cancellation patterns where contracts really match.
- [ ] Consolidate repeated SQL filter/facet fragments.
- [ ] Consolidate repeated cache/LRU/TTL implementations.
- [ ] Consolidate repeated source-independent normalization only at the correct owner package.
- [ ] Find duplicated CSS/layout utilities before adding more component-specific variants.

A duplicate is not automatically moved into local `shared/`: ownership rules above take precedence.

---

## Phase 9 — P3 tails and dead code

- [ ] Inventory TODO/FIXME/HACK/deprecated markers.
- [ ] Remove obsolete compatibility branches once upstream canonicalization is guaranteed.
- [ ] Remove unreachable/dead routes and stale feature flags.
- [ ] Remove unused types/helpers/styles/components/assets.
- [ ] Remove old migration/backfill code after versioned migrations supersede it.
- [ ] Remove comments that describe bugs/temporary behavior no longer present.
- [ ] Keep intentional compatibility code documented with a removal condition.

---

## Phase 10 — consistency and final quality pass

- [ ] Standardize error/result contracts for internal fetch wrappers.
- [ ] Standardize logging and redact sensitive values.
- [ ] Standardize env/config validation at startup.
- [ ] Review security headers/CSP at the actual edge configuration; do not assume repository headers are the whole production path.
- [ ] Run lint, typecheck, tests, build and service-specific smoke tests.
- [ ] Re-run god-file/duplication/tail/package-boundary inventory and close or explicitly defer every remaining item.

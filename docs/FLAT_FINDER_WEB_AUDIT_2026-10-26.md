### 1. Фоновая загрузка получает данные, но не показывает их — P1

**Код:** [background-ветка useFlatFeed](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatFeed.ts:228), [warm polling](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatFeed.ts:88).

В background-ветке обновляются `total`, кэш, ошибки и `warming`, после чего функция возвращается. Присваивания `listings` и `nextCursor` находятся ниже и не выполняются. Это затрагивает и warm polling, и повторную проверку закэшированной первой страницы.

**Воспроизведение:** первый ответ — `{ listings: [], warming: true }`, следующий — 40 результатов, карточка и cursor, `warming: false`. В UI получается `total = 40`, но `listings = []` и прежний cursor; polling прекращается. Второй тест показывает, что при повторной проверке кэша карточка `old` не заменяется на `fresh`.

**Исправление:** определить единую политику применения актуальной первой страницы, включая cursor. Для warm completion обязательно применять выдачу; при обновлении уже просмотренного списка явно учитывать добавленные страницы и позицию прокрутки. Текущая ветка не реализует обещанное комментарием обновление видимых результатов.

### 2. Ответ, начатый до выхода, восстанавливает данные аккаунта — P1

**Код:** [syncFavorites](C:/Users/kubai/IdeaProjects/sample_project/app/pages/flat-finder/[...slug].vue:590), [очистка по signedOutAt](C:/Users/kubai/IdeaProjects/sample_project/app/pages/flat-finder/[...slug].vue:609).

`syncFavorites()` сохраняет локальный `before`, ждёт `pull()`, затем без проверки сессии вызывает `mergeFavorites(remote)` и `seed(before...)`. Watcher выхода очищает коллекцию, но не инвалидирует выполняющуюся синхронизацию.

**Воспроизведение:** начать pull → очистить избранное так же, как это делает watcher выхода → завершить старый pull. Избранное снова содержит данные прежней сессии. Код также продолжает additive import из захваченного `before`; реальные серверные данные в аудите не изменялись.

**Исправление:** привязать операции к поколению/области аккаунта, инвалидировать их при выходе, удалении и размонтировании. После каждого await проверять, что сессия ещё актуальна. Отменять запросы, где это возможно; не выполнять seed из устаревшей сессии. Vue документирует отмену устаревших side effects через cleanup: [Watchers](https://vuejs.org/guide/essentials/watchers.html).

### 3. Локальные коллекции не используют введённую уникальную идентичность — P2

**Код:** [getId страницы](C:/Users/kubai/IdeaProjects/sample_project/app/pages/flat-finder/[...slug].vue:229), [toggleFavorite](C:/Users/kubai/IdeaProjects/sample_project/app/composables/search/useSavedCollections.ts:105), [полный ключ уже существует](C:/Users/kubai/IdeaProjects/sample_project/app/utils/flats/listingKey.ts).

`useSavedCollections` подключён с `getId: item => item.id`; membership-проверки и сопоставление `remoteIds` тоже используют только id. При этом серверная синхронизация и Vue `:key` идентифицируют объявление по `source:country:id`.

**Уточнение после проверки миграций и регистрации:** уникальная идентичность уже введена. Глобальный `publicId` берётся из `listings.id`, а синхронизация сохранений использует составной `item_key`. Поле DTO `id` осталось идентификатором источника: [формирование ответа backend](C:/Users/kubai/IdeaProjects/whiteslove.me-backend-platform/apps/flats/src/routes/listing-item-routes.js:81), [миграция publicId](C:/Users/kubai/IdeaProjects/whiteslove.me-backend-platform/apps/flats/migrations/018_listing_public_id.sql:1). Регистрация связывает владельца сохранений, но не заменяет DTO `id` на `publicId`.

**Воспроизведение:** два тестовых объявления OLX имеют одинаковый source `id=42`, разные страны и разные `publicId`. Сохранение второго интерпретируется как удаление первого — остаётся ноль элементов вместо двух. Это проверка поведения при коллизии, допустимой текущим контрактом `UNIQUE(source, country, source_id)`, а не обнаруженная пара дубликатов в production. Исходный синтетический пример OLX/Telegram с голым `id=42` уточнён: текущий Telegram scraper сам добавляет префикс канала.

**Исправление:** использовать существующий `flatListingKey` на всех границах коллекций: getId, isFavorite/isHidden, hiddenIds, merge/seed и поиск элемента. Одного изменения getId недостаточно: вызывающий код также передаёт только id. Существующие сохранённые payload позволяют вычислять полный ключ без восстановления семантики из текста.

### 4. Кэш перевода разделяет текст между разными объявлениями — P2

**Код:** [ключ кэша useFlatTranslation](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatTranslation.ts:16), [prepareTranslation](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatTranslation.ts:34).

Ключ имеет вид `id:language`, без source/country и версии текста. При повторяющемся source id перевод одного объявления доступен другому с отличающимся `publicId`. Также после изменения description того же объявления может использоваться прежний перевод.

**Воспроизведение:** перевести A → открыть B с тем же source id, другой страной, другим `publicId` и description → `prepareTranslation(B)` сразу возвращает перевод A. Это синтетическая проверка; фактические коллизии production-данных не устанавливались.

**Исправление:** полный ключ объявления + язык + fingerprint исходного текста/версия содержимого. Проверки актуальности ответа также должны использовать полную идентичность.

### 5. Смена языка не инвалидирует перевод — P2

**Код:** [начало перевода](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatTranslation.ts:69), [принятие результата](C:/Users/kubai/IdeaProjects/sample_project/app/composables/flats/useFlatTranslation.ts:40).

В начале операции фиксируется target language, но после ответа проверяются только requestId и id объявления. Watcher языка, сбрасывающий/переподготавливающий перевод, отсутствует и в composable, и на странице.

**Воспроизведение:** начать RU-перевод → поменять locale на EN → завершить RU-запрос. Русский текст принимается в текущем интерфейсе EN.

**Исправление:** при смене языка отменять polling, увеличивать поколение операции и переключать состояние на кэш нового языка. Перед принятием результата сравнивать текущий язык с запрошенным. Отмену незавершённого HTTP-запроса добавить отдельно от остановки таймера polling.

### 6. Карта не следует персональной вкладке — P2

**Код:** [передача points страницы](C:/Users/kubai/IdeaProjects/sample_project/app/pages/flat-finder/[...slug].vue:810), [сбор renderedPoints](C:/Users/kubai/IdeaProjects/sample_project/app/components/flats/FlatMap.client.vue:497), [загрузка общей карты](C:/Users/kubai/IdeaProjects/sample_project/app/components/flats/FlatMap.client.vue:397).

Страница передаёт карте точки `displayedListings`, то есть избранное/скрытые/историю текущей вкладки. Однако FlatMap независимо загружает общую выдачу и всегда объединяет её с переданными точками. Режим персональной коллекции не передаётся, путь вкладки не участвует в выборе режима данных.

**Воспроизведение:** в points одна избранная квартира, в remotePoints постороннее объявление. Результат computed содержит оба объекта. Для активной выдачи такой merge нужен, но на вкладке избранного он нарушает соответствие списка и карты. Скрытое в активном списке объявление также может оставаться среди общих remotePoints.

**Исправление:** явно разделить режим общей поисковой карты и режим переданной коллекции. В персональном режиме рисовать только её точки; в поисковом режиме применять согласованную политику скрытых записей. Источник данных карты должен быть частью контракта компонента.

### 7. Карта считает неудачный запрос уже загруженным — P2

**Код:** [lastMapFeedKey и обработка ошибки](C:/Users/kubai/IdeaProjects/sample_project/app/components/flats/FlatMap.client.vue:397).

`lastMapFeedKey` меняется до успешного ответа. Если запрос новых фильтров падает, remotePoints остаются от прежней выдачи. Следующий вызов для нового ключа завершается по условию `key === lastMapFeedKey && remotePoints.length`, хотя данные относятся к старому ключу.

**Воспроизведение:** есть маркеры RO → запросить UA с сетевой ошибкой → повторить UA. За два вызова производится только одна попытка HTTP; старые точки остаются.

**Исправление:** разделить ключ отображаемых данных, успешного ответа и запроса в работе. Не отмечать ошибку как успешную загрузку, разрешать управляемый retry и показывать состояние устаревших данных. При смене области не выдавать точки прежней области за результат новых фильтров. Аналогично проверить lifecycle `loadExtraGeo()` при очистке city/country.

### 9. Модальность не реализована для клавиатуры — P2

**Код:** [общий Modal](C:/Users/kubai/IdeaProjects/sample_project/app/components/u/Modal.vue:69), [dialog](C:/Users/kubai/IdeaProjects/sample_project/app/components/u/Modal.vue:94), [кликабельная карточка](C:/Users/kubai/IdeaProjects/sample_project/app/components/flats/FlatCard.vue:115).

## Архитектура и Best Practices

**Что уже хорошо:** выделены фильтры, сериализация маршрута, presentation, перевод, метаданные и сохранения; есть типизированные DTO, latest-request/AbortController, ограниченные TTL-кэши, dedupe пагинации и общие search-компоненты. Ключи Vue-карточек составные. Географические labels/DOM-маркеры проходят безопасное формирование через textContent и проверку цветов; это покрыто исполняемым тестом. Секреты installation находятся в httpOnly-cookie серверного адаптера. Это полезная основа, которую стоит сохранять.

**Разделить два самых крупных модуля.** FlatMap — 1906 строк, страница — 1574; вместе около 45% предметного фронтенда. В FlatMap смешаны сеть, Leaflet, слои, clustering, камера, выбранные фильтры и контролы. На странице одновременно живут session sync, коллекции, выдача, URL, popup и таблица свойств. Выделять по ответственности и контрактам: map data source, map selection/camera, слои, синхронизация коллекций и details controller. Простое разнесение кусков файла без устранения скрытых зависимостей от route не решит проблему.

**Один владелец идентичности и области данных.** Использовать существующий `flatListingKey`, единый session generation и явный режим карты. Сейчас соседние слои по-разному понимают «тот же объект», «эта сессия» и «эта выдача» — именно на этих границах воспроизведены дефекты.

**Объединить географические запросы.** `useGeoCityCatalog` и FlatMap.loadExtraGeo независимо обращаются к `/flats-geo-city` для country/city/locale, имеют отдельные состояния и правила повторов. Общий каталог уже умеет переиспользовать pending-запрос. Расширить существующий слой, чтобы карта использовала тот же snapshot/поток данных, сохраняя различие DTO-групп и descendants. Количество запросов в реальном браузере в аудите не измерялось.

**Не блокировать всю форму при загрузке результатов.** UiResultsLoader оборачивает форму, карту и выдачу; его content получает inert при loading. Это делает фильтры недоступными во время медленного запроса, хотя useLatestRequest способен отменять устаревшие операции. Ограничить loader результатами и сохранить доступ к фильтрам/отмене. Проверить вложенные scroll locks и delayed callbacks при unmount.

**Сохранить числовые данные числовыми.** FlatCard.displayedUsdPrice пытается восстановить число из форматированного `convertedPrice`, удаляя все недесятичные символы. Передавать отдельный `priceUsd`/ratio в presentation-модель и форматировать только при отображении. Это снижает зависимость логики от локали и подписи валюты.

**Различать доступность локального UI и успешность синхронизации.** `useFlatFavoriteSync.live` навсегда отключает отправку после одной ошибки на время жизни страницы, без очереди/видимого статуса. Локальная работа должна сохраняться, но пользователю полезно видеть ожидающие изменения и иметь управляемый retry. Для аккаунта определить начальное additive merge отдельно от последующей синхронизации удалений; сейчас безусловный union может вернуть запись, удалённую на другом устройстве. Последний сценарий в дополнительный набор тестов не включён.

**Добавлять поведенческие тесты поверх source checks.** Значительная часть существующих регрессий проверяет наличие строк/regex в исходниках. Например, тест background revalidation проверяет вызов и комментарии, но не проверяет новые `listings` и cursor. Такие проверки полезны для архитектурных запретов, но не подтверждают поведение. Для composables нужны контролируемые HTTP-ответы и реальные refs; для SFC — mount/SSR и действия пользователя. Не требуется переносить весь набор на другой test runner, чтобы начать это делать.

**Расплатиться с предупреждениями постепенно.** По 44 проверенным файлам: 156 `max-statements-per-line`, 51 `no-explicit-any`, 44 `attributes-order`, 44 `html-self-closing`, 1 `first-attribute-linebreak`. Большая часть приходится на FlatMap и страницу. Сначала заменить any на типы DTO/Leaflet на границах, раскрыть сложный control flow; форматирование атрибутов исправлять отдельно от функциональных изменений, чтобы не смешивать diff.

**Управление внешними ссылками.** В popup `active.url` напрямую становится href; локальный shapeListing переписывает фотографии, но URL объявления оставляет как есть. Гарантию допустимых схем нужно проверить у владельца upstream DTO; для восстановления из localStorage нужна проверка входной структуры. Достижимая XSS-цепочка в аудите не доказана. [Vue Security](https://vuejs.org/guide/best-practices/security) отдельно объясняет, что автоматическое экранирование атрибутов не проверяет URL-схемы.

**Производительность и SSR требуют измерения.** Первый feed стартует только из onMounted, поэтому серверный HTML не содержит загруженных квартир. Уточнить продуктовый контракт SSR для общей поисковой страницы; персональные данные должны оставаться изолированными. Clustering уже использует spatial grid, поэтому объявлять карту квадратичной по коду оснований нет. Большие geo-структуры и Leaflet instances стоит профилировать отдельно; FPS, INP, LCP и память реального браузера не измерялись.
